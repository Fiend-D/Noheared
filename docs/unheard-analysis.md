# 《疑案追声》玩法拆解与重构设计

本文从公开可见的玩法、表现和交互出发，拆解《疑案追声》（Unheard，NExT Studios，Unity 制作）的核心系统，并说明本项目 Godot 版对应的设计决策。不涉及对原作的解包，也不复用原作的任何资源。

## 1. 原作核心体验

玩家是一个“看不见的听众”。案件是一段固定长度的录音：几名角色在一张蓝图风格的多房间地图上移动、交谈。玩家只能听到自己所在房间（以及隔壁隐约传来）的声音，必须反复倒带、换房间“跟人”，拼出完整事件，最后指认每个圆点的身份并回答案件问题。

手感上最关键的三点：

1. **时间可随意操纵且绝对一致**：暂停、拖动、倒退、变速后，人物位置和声音都与“录像”完全一致。
2. **声音有空间感**：同房间的声音清晰且有左右方位；隔着门墙会发闷、变小；枪声、尖叫能传得很远。
3. **信息靠“听到”获得**：字幕只显示真正听见的台词，听过的内容会进笔记，可以点回去重听。

## 2. 子系统拆解

| 子系统 | 原作表现 | 推断的实现方式 |
| --- | --- | --- |
| 时间轴 | 进度条、暂停、倒退、快进，变速时声音不变调 | 全局时钟驱动所有对象；状态都是时间的函数；音频按偏移量 seek，变速时做 pitch 补偿 |
| 人物 | 带编号的彩色圆点，说话时有声波纹，走动有脚步声 | 剧本预设的关键帧路径，按时间插值，穿门走预设路线 |
| 监听者 | 在房间之间移动的“耳朵” | 音频监听点；按房间关系决定可听性和滤波 |
| 声学 | 同房间清晰，隔壁发闷，大声事件穿墙 | 房间连通图 + 混音总线（低通、混响、衰减） |
| 字幕与笔记 | 只显示听到的台词；记录可回跳 | 可听判定后写入记录，条目带时间戳 |
| 推理 | 指认身份、回答问题、评分、揭示真相 | 静态题库 + 答案比对 + 存档 |
| 地图 | 多楼层蓝图，房间名、门洞、楼梯标记 | 场景节点描述房间多边形、门、楼梯 |

## 3. 旧版（PyQt + pygame）的问题

- `pygame.mixer` 被锁在单声道，没有方位感，`set_pan` 是空实现。
- 拖动进度条时把整条录音切片后重建 `Sound`，跳转卡顿；时间用 `perf_counter` 估算，长案件会漂移。
- 人物移动依赖运行时寻路、推挤和楼梯“传送”，位置取决于帧历史，倒退或拖动后与剧本不一致。
- 每个角色一条整段录音，只按距离线性调音量，没有隔墙效果。
- 没有编辑工具，坐标和时间全靠手改 JSON。

## 4. Godot 版设计决策

### 4.1 确定性时间轴

- `TimelineClock` 是唯一的时间源。所有系统只读当前时间 `t`，不保存帧间状态。
- 人物位置是纯函数 `position(track, t)`：在关键帧之间线性插值。跨房间的路线（门洞、楼梯口）在数据中写成关键帧，运行时不寻路。
- 台词按句切成独立片段（`VoiceLine`）。seek 后只需要让“此刻正在说”的句子从对应偏移量播放，其余句子按时间触发。播放中定期把音频播放位置与时钟比对，误差超过阈值就重新对齐。
- 变速播放时设置 `pitch_scale`，并在 Master 总线上用 `AudioEffectPitchShift` 补偿音高，保证快进时声音不变调。

### 4.2 声学

监听者与声源之间的关系由房间连通图决定：

| 关系 | 处理 |
| --- | --- |
| 同一房间 | `Room` 总线，`AudioStreamPlayer2D` 距离衰减 + 左右声像，轻度混响 |
| 隔一道门（或楼梯） | `Muffled` 总线（低通 + 混响），额外衰减 |
| 更远 | 静音，除非是大音量事件 |
| 大音量事件（`loudness` 高） | 按跳数逐级衰减，可穿透多个房间 |

总线或音量切换时做短时渐变，避免爆音。

### 4.3 数据与工具

- 运行时读取 Godot `Resource`（`CaseData`、`CharacterData`、`TrackKey`、`VoiceLine`、`SfxEvent`、`Question`），地图是独立的 `.tscn`。
- 案件可以与 JSON 互相转换，方便用 Python 脚本批量生成（TTS 等）。
- 编辑器插件提供时间轴面板：拖动台词块和关键帧、在地图上预览任意时刻的人物位置，并一键校验数据。

## 5. 与原作的刻意差异

- 楼层用标签页切换显示；旧案件里上下层画在同一画布的不同区域，迁移后按楼层分组。
- 监听者在房间内可以自由定位（影响左右声像），但跨房间时直接移动到目标位置，不做步行动画上的碰撞。
